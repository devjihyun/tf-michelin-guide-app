# 마일스톤

이 문서는 [unified_spec.md](/c:/Users/jihyun.kim/toy/docs/unified_spec.md) 기준의 실제 구현 우선순위를 정리한 문서다.

## M0. 기획 확정

- 통합 기준안 확정
- 라우트 명칭 `restaurants` 기준으로 통일
- MVP 범위 확정
- 후순위 기능 분리

산출물:

- 통합 기준 문서
- IA / API / 데이터 모델 기준선

## M1. 서비스 골격

목표:

- 최초 사용자는 초대코드로 회사 / 조직을 확인한 뒤 계정을 등록할 수 있어야 한다.
- 기존 사용자는 초대코드 재입력 없이 계정 로그인으로 서비스에 진입할 수 있어야 한다.
- 로그인 유지 상태라면 바로 서비스에 진입할 수 있어야 한다.
- 승인된 맛집 목록과 상세를 읽을 수 있어야 한다.

구현 항목:

- 초대코드 검증
- 회사 / 조직 확인
- 닉네임 + 패스워드 계정 등록
- 계정 로그인
- 로그인 유지 확인
- 기본 사용자 식별
- `organizations`, `users`, `access_codes`, `restaurants` 테이블
- 맛집 리스트 API
- 맛집 상세 API
- `/access`
- `/restaurants`
- `/restaurants/:id`

완료 기준:

- 최초 접속자는 초대코드 확인 후 계정 등록 가능
- 다음 접속부터 초대코드 재입력 없이 로그인 가능
- 로그인 유지 시 `/restaurants` 바로 진입 가능
- 승인된 맛집만 리스트에 노출
- 상세에서 기본 정보 확인 가능

## M2. 사용자 참여

목표:

- 사용자가 맛집을 등록하고 평가할 수 있어야 한다.

구현 항목:

- 맛집 등록
- 태그 저장 / 조회
- 평점 등록
- 추천 / 비추천
- 등록 UI 모달
- `restaurant_tags`, `ratings`, `votes` 테이블

완료 기준:

- 사용자가 맛집 등록 가능
- 같은 사용자의 평점은 업체당 1회 기준으로 관리
- 같은 사용자의 추천 / 비추천은 업체당 1회 기준으로 관리

## M3. 커뮤니티 기능

목표:

- 등록된 맛집에 대해 사용자 상호작용이 누적되어야 한다.

구현 항목:

- 댓글 작성 / 수정 / 삭제
- 마이페이지
- 내 등록 맛집 조회
- 활동 내역 조회
- 포인트 적립 이력
- `comments`, `point_histories` 테이블

완료 기준:

- 상세에서 댓글 CRUD 가능
- 마이페이지에서 내 활동 확인 가능
- 포인트 적립 이력이 누적됨

## M4. 운영 기능

목표:

- 관리자 승인 흐름과 삭제 요청 흐름이 완성되어야 한다.

구현 항목:

- 관리자 승인 / 반려
- 삭제 요청 생성
- 삭제 요청 처리
- 관리자 페이지
- `deletion_requests` 테이블

완료 기준:

- 등록된 맛집은 승인 전까지 공개되지 않음
- 사용자는 삭제 요청 가능
- 관리자는 승인 / 반려 / 삭제 요청 처리가 가능

## M5. 후순위 고도화

구현 항목:

- 랭킹
- 홈 추천 영역
- 외부 업체 검색 / 자동완성 고도화
- 이미지 처리 확장

비고:

- 서비스 운영과 핵심 사용자 흐름에 직접 필요하지 않으므로 후순위로 둔다.
